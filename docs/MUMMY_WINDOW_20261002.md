# 1ninn 2分5秒の見逃し調査と選択順修正

## 実測と再現を分けた結論

みいらおとこはspecies108/model z021aで、自動観測の初期4モデルに含まれる。ROMのz021a_f資産も存在し、候補不足がこの場面の説明にはならない。

実映像124.75/125.00秒ではCPU候補2番、125.25～126.75秒では1番に対象が入る。600msの推論応答fixtureを使うと、125.75秒で未処理1番より待ち時間の長い背景3番、126.25秒で背景4番が先行した。これはユーザー環境の処理時間・履歴そのものを再現したとは限らない。

実際のcloud Chromeで正確な候補cropを手動で渡し、DINOv2 CPU/WASM int8、_f、quick、初期4モデル、64保存済み姿勢featureを使って照合した。

数値は未校正の類似度で、確率・確定認識ではない。手動で渡した実cropの分類であり、動画の自動選択全体の実測ではない。後半2つの有用なcropを選択処理が落とす一方、最初のcropには分類の混同もある。

## 最小の選択修正

CPU候補の安全性・cooldown判定後、上位1・2を下位候補とは別の優先段階に置く。下位候補の待ち時間だけでは処理可能な上位を追い越せない。下位は上位がcooldown中・不在・不適格の場合に処理する。上位候補が絶えず現れる場合、下位を処理しないことを許容する。

既存の任意DINO補助経路は変更しない。補助が有効なときの追加crop選択までCPU優先順位の保証を広げるものではない。分類器・領域抽出・推論頻度・1件ずつの実行・元画素所有権は変更しない。

- 125秒の600ms fixture: 敵cropの識別要求0→2件、全要求14件のまま
- 同窓の100/700ms fixture: 1→2件、1000ms:2→2件。準備1000msの4条件も2→2件
- 既存75～85秒の8条件: 7条件同数、100ms/準備0の1条件でcompact body crop3→4件。全要求数は各条件で不変
- 合計217件の修正後要求は、同一source frameの指定範囲と画素hashが一致
- observer49件、page/lifecycle224件、統合build、独立レビューが通過

WebGPU、全動画の種精度、背景の誤認除去は未検証。この修正だけで125.00秒の種類混同が直ったとはしない。公開後のブラウザ確認は別途行う。
