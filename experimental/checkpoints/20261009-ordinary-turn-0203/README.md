# Conditional ordinary-turn target constraints

This stage keeps the published stable-heading generator unchanged by default. A separate opt-in `turnPhaseResolver` adds a one-prefix orientation necessary condition. An owner callback retains its finite support once; occupancy rows refer to that support key. Source IDs, ROM identity, endpoint species/table intersections and exact eligible-node order still come from the existing generator.

The actual saved 5898 F05 input contains 31 linked endpoint intervals. The first orientation-only measurement found 1,084 compatible node hypotheses in 14 intervals, including phase zero. Only 92 node hypotheses in 13 intervals contain a positive phase. These are not full motion matches. For the separate no-post-correction displacement hypothesis, a changed XYZ endpoint excludes phase zero; it does not establish an update count from PTS.

The explicit branch assumes the source ordinary state1 entry was reached, retained turnRate808, followed by one supported orientation-prefix invocation after a target choice at the proposed root. Other initialization, multiple updates, corrections, different actors, unknown species, no-event and other consumers remain possible. The original event predicates and failed stable-heading checks remain. The new predicate is conditional on the target-choice draw; it is not a new draw for each observation.

`native-turn-phase.mjs` inverts the exact supplied orientation leaf across ROM-facing-equivalent source angles, enumerates each pre-saturation integer phase, and represents the constant tail as an interval through 65535. That domain is the existing bounded kernel's supported phase domain, not a measured clock range. Translation, actor ownership, full source tick and current AT are unresolved.

`measure-real-turn-predicates.mjs` uses the original WASM orientation arithmetic with explicitly synthetic neutral input words only for its arithmetic oracle; these are never video runtime inputs or current state. It fairly enumerates at most the existing 4096 route-row budget across all linked intervals and compiles generated modulo events with the existing compiler. Unvisited occupancy/target alternatives remain unknown; numerical event counts are never summed or intersected without a source gap.

The C difference extracts that same arithmetic into `monster_motion_turn_angle`, so the eventual production caller can avoid synthetic prefix inputs. The initial build failed because clang was absent (BUILD_STATUS.json retained). The parent subsequently supplied verified LLVM19.1.7; the new export was built and 1,723,188 actual saved-hypothesis arithmetic calls matched the original WASM exactly. All generated numerical events matched. No published source or WASM has been changed. The production MonsterMovementKernel.orientationStep and source-bound resolver have been exercised using the real ROM and a saved endpoint. Before browser integration the owner-held support registry must accompany its references across serialization and engine/code identity must be updated. This stage is not yet a browser controller integration.
